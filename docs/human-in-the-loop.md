# MiniCodex Human-in-the-loop

**简体中文** · [English](human-in-the-loop.en.md)

Human-in-the-loop 是安全策略和宿主 UI 之间的任务级审批协议。它只处理 Harness 已判定为“允许但需要注意”的 `CAUTION` 操作，不改变安全策略本身。

## 执行流程

```text
工具调用 → SafetyPolicy
              ├─ SAFE → 直接执行
              ├─ CAUTION → ApprovalCoordinator → 允许 / 拒绝
              └─ BLOCKED → 直接拒绝，不可审批绕过
```

当前会触发审批的典型情况包括：

- 安装或修改依赖；
- 使用 `curl` / `wget` 访问外部网络；
- 修改任务开始前已有未提交内容的文件；
- 修改存在 Git 冲突的文件。

## 用户决策

| 决策 | 作用域 | 结果 |
| --- | --- | --- |
| 允许一次 | 当前工具调用 | 执行一次，后续同类操作仍需询问 |
| 本任务允许 | 当前任务与同一安全规则 | 当前任务后续同类操作自动通过；新任务会清空授权 |
| 拒绝 | 当前工具调用 | 不执行工具，向 Agent 返回 `permission_denied` |

拒绝不是伪造成功。Agent 必须寻找不需要该权限的替代方案，或把它记录为具体阻断原因。等待审批有五分钟超时并失败关闭；Stop 会拒绝待处理审批，再通过现有协作式取消边界结束任务。

## 安全边界

- 工作区逃逸、破坏性命令、Git 写操作、checkpoint 绕过、未授权编辑和反测试作弊等 `BLOCKED` 操作不能通过 UI 解锁。
- UI 只接收 `path`、`command`、`package`、`import_name`、`argv`、`url` 和 `port` 等白名单参数。
- 参数经过敏感字段脱敏、内联凭证脱敏、长度限制与数组数量限制。
- 审批 ID 必须匹配当前待处理请求；过期或重复决策失败关闭。
- “本任务允许”不会跨任务、进程或工作区持久化。

## 当前范围

审批宿主目前由本地 Web UI 提供。CLI 仍保持原有的自主警示行为。后续工作包括可选的 Review / Auto / Read-only 运行模式、审批审计事件，以及更细粒度的 Diff 审查。
