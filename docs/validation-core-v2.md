# Validation Core V2

MiniCodex 的验证链只有七个权威概念：

1. `TaskRequirement.contract`：类型化、与工具无关的机器契约；中文描述只用于展示。
2. `ValidationCheck`：一个当前编辑版本的必需证明义务，可显式关联多个需求。
3. `ValidatorResolver`：只按契约和已注册能力解析工具、参数与目标，不解析自然语言。
4. `ValidationExecutor`：Harness 通过既有安全、沙箱、检查点和工具执行栈直接运行已解析验证。
5. `ValidationEvidence`：仅在验证器实际执行后产生，并携带明确 `check_id`。
6. `ValidationLedger`：保存编辑版本、必需检查、执行观察与证据，是验证真相的唯一来源。
7. `TaskCompletionPolicy`：全部当前版本必需检查有账本证明时才返回 READY。

LLM 负责理解请求、检查源码和编辑代码。Harness 负责解析并执行确定性的验证机械步骤；
已解析验证不会再交给 LLM 重选工具。

关键约束：

- 非执行事件（参数错误、限制、安全拦截、重复调用、工具不可用）只记录执行观察，不产生证据。
- 匿名或手工诊断证据不能关闭必需检查。
- 编辑递增版本并使旧版本证明自然失效。
- 相同契约可合并为一个多需求检查；不会因为一个命令通过而隐式证明无关需求。
- 无编辑任务只需完成已物化的验收检查；没有编辑就不会凭空增加编辑诱发的回归义务。
- 能力缺失或一次有界目标解析失败会形成明确阻塞，不会消耗主循环直到步数上限。
