# MiniCodex v0.3.0 — Local Web Workspace

[简体中文](v0.3.0.zh-CN.md) · **English**

MiniCodex v0.3.0 adds the first usable browser workspace on top of the existing deterministic Runtime, bringing repository navigation, Agent execution, validation activity, and change review into one local product interface.

## Highlights

- Launch a dependency-free local Web workspace with `minicodex ui --workspace /path/to/project`.
- File tree and search, code preview, Git diff, Agent chat, live task phases, and a Trace activity terminal.
- Task-level **Accept / Reject** backed by the existing checkpoint rollback engine. Reject does not use `git reset` and refuses to overwrite external changes made after a checkpoint.
- A Stop control that uses Runtime cooperative cancellation to prevent subsequent model steps and tool calls.
- Chinese and English interface switching without modifying the original task text.

## Security boundary

- The HTTP service may bind only to loopback addresses.
- Mutation requests require a random session token and pass Host and same-origin checks.
- Responses enable CSP, frame, MIME, and Referrer security headers.
- File preview is protected by workspace boundaries, size limits, binary and symlink rejection, and credential-file filtering.
- The UI reuses the same Agent, safety, validation, and completion gates as the CLI instead of maintaining a second execution path.

## Quality evidence

- 689 deterministic project tests passed.
- CI covers Python 3.11, 3.12, and 3.13.
- Python compilation, JavaScript syntax, and Git whitespace checks passed.
- The wheel was installed outside the source tree and verified to include UI assets and the `minicodex ui` command.
- Responsive checks passed at 390 px, 768 px, and desktop widths with no browser console warnings or errors.

## Current limitations

- One Agent task runs at a time.
- Diff review and Accept / Reject apply to the whole task; per-command approval is not available yet.
- The activity terminal is a read-only Trace view, not an arbitrary shell.
- Messages, in-progress state, and Reject checkpoints remain process-local; unfinished tasks cannot resume after the service closes.
- The local service is neither a remote multi-user application nor a kernel-level container sandbox.
