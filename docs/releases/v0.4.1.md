# MiniCodex v0.4.1 — Regression evidence fix

[简体中文](v0.4.1.zh-CN.md) · **English**

MiniCodex v0.4.1 fixes an internal completion-gate defect found in the v0.4.0 Benchmark V1 R2 run. Two refactoring tasks satisfied their independent hidden oracles, but their passing semantic regression checks did not become ledger proof. The Agent kept working until it exhausted its step budget.

## Fix

- Preserve the requested `acceptance` or `regression` purpose when normalizing semantic, static Web, and browser validator results. Previously, these results were always tagged `acceptance`, so the ledger rejected them for regression checks.
- Keep the existing proof requirements for check identity, current edit revision, sufficient strength, and non-agent-created tests. No validation gate was disabled.
- Add deterministic regression tests for the parser-extraction and Web-script-extraction completion chains.

## Verification

- 710 deterministic project tests passed; the offline VibeBench passed 15/15 cases.
- A one-run DeepSeek `deepseek-v4-flash` targeted retest at temperature 0 and 20 maximum steps passed **2/2** isolated fixtures: `refactor_extract_parser` and `refactor_extract_web_script`. Both independent hidden oracles passed, both internal completion statuses were `ready`, and neither task exhausted its step budget.
- The targeted retest measured code commit `ff427d2e040c173fc12ced545d95c09d3be206d0` before this release-metadata commit. It is **not** a repeat of the complete 30-case benchmark and does not replace the published v0.4.0 result.
