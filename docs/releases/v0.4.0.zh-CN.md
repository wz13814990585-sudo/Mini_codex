# MiniCodex v0.4.0 — Human-in-the-loop

**简体中文** · [English](v0.4.0.md)

MiniCodex v0.4.0 将本地 Web 工作台升级为有人监督的编码流程。用户可以为每个任务选择权限模式，在警示级操作执行前逐项确认，审查生成的 Diff，最后接受或拒绝整个任务。

## 主要能力

- 每任务的**审查**、**自动**和**只读**权限模式。
- 审查模式提供**允许一次**、**本任务允许**和**拒绝**，并展示有界、脱敏的操作预览。
- Agent 等待人工决策时支持协作式取消与超时处理。
- 审批请求和处理结果持续写入 Trace 审计记录。
- 接受或拒绝任务前，可在完整 Diff 与单个变更文件之间切换审查。
- CLI 与 Web UI 继续复用相同的确定性 Runtime、验证门禁和 checkpoint rollback 语义。

## 安全边界

- 确定性硬阻断不能通过人工审批绕过。
- 只读模式会从模型工具 schema 中移除副作用工具，并在执行边界独立拒绝编辑、进程、验证进程和依赖安装。
- 审批预览使用显式参数白名单，并对敏感值进行脱敏。
- UI 继续只监听回环地址，并使用 Host、同源和会话令牌校验保护变更请求。
- CLI 保持向后兼容；除非 UI 任务另行选择，默认使用自动模式。

## 质量证据

- 本地 708 项确定性项目测试通过。
- CI 覆盖 Python 3.11、3.12 和 3.13，并包含打包检查。
- wheel 在源码目录外完成安装验证，确认版本为 `0.4.0` 且包含 Web UI 静态资源。
- 使用真实浏览器验证了审查审批、审计 Trace、文件级 Diff、Accept、Reject 和权限模式流程。

本次发布的 Benchmark 刻意安排在正式发布后运行，以确保公开结果衡量的是不可变的 release commit。公开报告与机器可读摘要会作为附件添加到 [GitHub Release](https://github.com/wz13814990585-sudo/Mini_codex/releases/tag/v0.4.0)。

## 当前限制

- 一次只运行一个 Agent 任务，运行中状态仍只存在于当前进程。
- Accept / Reject 以整个任务为原子单位，暂不支持只接受部分文件或 hunk。
- 审批授权只在当前任务内有效，服务重启后不会保留。
- 只读与安全策略属于应用层控制，不是内核级容器沙箱。
